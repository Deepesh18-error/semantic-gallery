# Phase 5 embedding contract and promotion

The desktop worker writes generation 2 vectors with a configuration that records the model, 3,072 dimensions, Phase 4 preprocessing version, configured passage token budget, retrieval formatting version, and L2 normalization. It embeds one semantic object per provider call. Each text passage is formatted as `title: ... | text: ...`; a search query is formatted as `task: search result | query: ...`. Image content is a single JPEG part without a text task prefix. The provider must return exactly one finite, nonzero vector with 3,072 dimensions. Vectors are normalized before caching and storage. Malformed responses stop the job as a provider rejection instead of silently entering the index.

The cache key includes the user, full configuration, semantic representation, and SHA-256 of the exact formatted text or derivative bytes. Repeated unchanged content and repeated queries use the cached vector without a provider call. Different passages are sent as separate requests: Gemini Embedding 2 aggregates multiple inputs into one embedding, so unrelated files must never be passed as a combined request. Independent calls can run concurrently through the Phase 3 worker and quota scheduler.

Generation 2 vector IDs include the file ID, file-version generation, representation, ordinal, index generation, and a configuration fingerprint. Search defaults to generation 1 via `SEMANTIC_GALLERY_SEARCH_GENERATION=1`; it never mixes generations in a vector query. Reindex in small batches with `queue_model_reindex --limit 20 --enqueue`. Existing generation 1 vectors remain stored during comparison.

## Probe and comparison

Use actual project/model limits from AI Studio and configure the provider quota first. With `SEMANTIC_GALLERY_STORAGE=desktop` and `GOOGLE_API_KEY` set, run `backend\venv\Scripts\python.exe backend\manage.py probe_embedding_contract --image PATH_TO_JPEG`. The probe embeds a query, a text passage, and optionally one representative JPEG as independent objects, checking dimensions and normalization. The probe consumes real quota. It cannot prove retrieval quality by itself.

Run the Phase 0 live evaluation once with `SEMANTIC_GALLERY_SEARCH_GENERATION=1` for baseline, then with `SEMANTIC_GALLERY_SEARCH_GENERATION=2` after the candidate files are reindexed. Use the same collection, labels, machine, and query set, saving both reports under ignored `evaluation/results/`. Compare them with `backend\venv\Scripts\python.exe evaluation\compare_generations.py BASELINE.json CANDIDATE.json`. The comparator checks per-case recall and type violations, overall recall, and a provisional p95 budget of 1.2 times baseline. Review the cases and timings manually before setting generation 2 as the normal search generation.

The repository has no access to your live Gemini quota configuration or personal gallery, so it cannot run the live probe or quality comparison automatically. Generation 2 remains unpromoted by default. The exact vector cache is local SQLite; it does not deduplicate simultaneous first-time calls from separate worker processes, though each call is still reserved against the shared quota. Optional descriptions remain outside the core vector generation.

While generation 1 remains active, newly imported images with only generation 2 vectors will not appear in semantic vector results; text passages remain available through full-text search. Promote after the evaluation gate to restore semantic retrieval for those new images. Keep the web process on one generation for each evaluation run; the live runner rejects a run in which the generation changes midstream. The comparator requires at least 20 timed queries per run before reporting promotion readiness.
