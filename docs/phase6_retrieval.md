# Phase 6 desktop retrieval

Run migration `0011` before using the new desktop search. It creates a local FTS5 index over filenames, titles, headings, passage text, OCR text, and any transcript segments. The migration backfills existing segments and keeps the index current when segments or filenames change. Filename retrieval also works for files whose extraction job has not completed.

Search resolves clear source-type words locally. A selected filter chip takes precedence; selecting All keeps the search broad. Inferred PDF requests also filter MIME to `application/pdf`, while a selected Document chip includes PDFs and DOCX. A query mentioning multiple types stays broad.

The retrieval path runs local keyword and filename search, then one non-generative query embedding when compatible vectors are available. It scans the active local vector generation once, reserving up to 20 distinct files per representation (visual, text, OCR, transcript, audio, video) and at most two vector segments per file within a representation. Keyword matches are also capped at two passages per file. Rank fusion operates on distinct file ranks, so many overlapping PDF passages cannot multiply a file's contribution. The response includes evidence channels, raw diagnostic scores, short previews, and page or timestamp locations. The UI no longer presents rank fusion as a percentage confidence.

The final relevance decision accepts an exact filename path, complete keyword term coverage, or a semantic candidate above `SEMANTIC_GALLERY_SEMANTIC_FLOOR`. The current default of `0.5` is provisional and must be calibrated on judged development examples. Run `evaluation/run.py --mode live --split development --debug-candidates --repetitions 3` against the desktop server, then use `evaluation/calibrate_relevance.py REPORT.json JUDGMENTS.json`. The judgments file maps case IDs to explicitly reviewed `positive` and `negative` filename lists. Set the proposed floor in the web process, rerun held-out and missing-answer queries, and compare recall, false positives, and p50/p95 before accepting it. Do not treat unjudged files as negatives.

Local tests prove that a synthetic food query returns the food images without Flash calls, a long PDF cannot fill the visual candidate group, an explicit Document chip overrides an image word, inferred PDF excludes DOCX, exact heading text is indexed, and an unrelated semantic candidate can yield `no_match`. The actual gallery's food and missing-answer outcomes remain a live evaluation gate because its indexed files and Gemini account limits are not available to the tests.
